# The accommodation review

The review classifies whether a theory's constructs accommodate a phenomenon. Disagreement between coders can come from an ambiguous codebook, a model limitation, an ambiguous text, or genuine misfit between theory and data. So disagreement alone is not evidence of misfit. The review uses three signals, each compared with thresholds stated in the codebook before coding begins.

| Signal | Definition |
|---|---|
| Human-human reliability | Cohen's kappa between two human coders |
| Model-human agreement | Cohen's kappa between the model and a human coder |
| Agreed residual | Among units both human coders judge relevant, the share both code as fitting no construct |

| Human-human reliability | Model-human agreement | Agreed residual | Interpretation |
|---|---|---|---|
| Low | Any | Any | Ambiguous codebook: revise definitions |
| High | Low | Low | Model limitation: change or tune the model |
| High | High | Low | Construct accommodates the phenomenon |
| High | Any | High | Misfit: characterize the agreed residual |

Reliability is reported for the codebook as a whole, on all codes, and for each construct, on a binary coding of that construct against everything else. The agreed residual is a property of the codebook: it is the same in every row of the per-construct report.

## Running the review

Human codes are supplied as a CSV file with the columns `unit_id`, `coder` and `code`, for exactly two coders:

```bash
getref review codebooks/institutional-pillars-ai.yaml \
  --human human_codes.csv \
  --outputs runs/institutional-pillars-ai/<hash>/outputs.jsonl
```

Only model outputs produced by the same codebook version are used.

## Current status

No human coding has been done yet. Coding a stratified benchmark sample by two trained coders is part of Stage 2. The files in `examples/` are **synthetic**. They were generated by `examples/make_synthetic.py` so that the review can be run end to end and its output inspected, and they support no substantive conclusion.

Planned additions to the review:
- sampling the units for human review with stored inclusion probabilities, for design-based correction of downstream estimates
- a log that classifies each codebook revision as peripheral, a construct split or a new construct
